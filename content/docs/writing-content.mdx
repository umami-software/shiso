Write docs as `.mdx` (or `.md`) files under `content/docs` and reference them in
`docs.json` navigation.

## File format

Each docs page usually starts with frontmatter:

```mdx
---
title: "Title of page"
description: "Optional description"
---

Welcome to Shiso.
```

## Frontmatter fields

- `title`: the page heading, sidebar fallback label, and `<title>` tag
- `description`: intro text under the title, also used as the meta description
- `noindex`: set `true` to mark the page `noindex` and keep it out of
  `sitemap.xml`
- `timestamp`: overrides the site-wide
  [`metadata.timestamp`](/docs/seo#last-modified-timestamps) setting for this
  page — `true` shows the last-updated date, `false` hides it

## MDX support

You can use standard Markdown plus React components directly in content:

```mdx
<Note>
  You can mix Markdown and components in the same page.
</Note>
```

## Available component surface in MDX

Shiso injects its built-in docs components into every page, so you can use them
without imports: `Tabs`, `Callout`, `Note`, `Card`, `Steps`, `CodeGroup`,
`ResponseField`, and more. See the Components tab for the full list.

## Icons

Components with an `icon` prop (and `icon` fields in `docs.json`) take names
from the [lucide](https://lucide.dev/icons) icon set:

```mdx
<Card title="Quickstart" icon="rocket" />
```

Icon names are collected from your content at build time, so an icon resolves
as soon as it appears in a source file — no imports or registration needed.

## Heading anchors and right rail

Heading IDs are generated and used for:

- anchor links
- right-side "On this page" navigation

Use meaningful heading text so anchors are readable.

## File organization conventions

- keep one concept per page
- use nested folders for nested routes (`components/tabs.mdx` -> `/docs/components/tabs`)
- prefer stable file slugs, and add a [redirect](/docs/seo#redirects) when a
  page has to move
