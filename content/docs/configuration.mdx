Shiso is configured with a single file: `docs.json`. All supported site
settings live there.

## Minimal example

```json
{
  "$schema": "./docs.schema.json",
  "theme": "shiso",
  "name": "My Docs",
  "colors": {
    "primary": "#16a34a"
  },
  "navigation": {
    "tabs": [
      {
        "tab": "Documentation",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["index", "quickstart", "configuration"]
          }
        ]
      }
    ]
  }
}
```

Only `navigation` is required. Everything else can be added as your site grows.

## How Shiso treats config keys

Every key in `docs.json` falls into one of three tiers:

| Tier | Behavior |
| --- | --- |
| **Supported** | Implemented and strictly validated. A malformed value fails the build. |
| **Reserved** | Recognized but not implemented yet. Accepted and ignored, with a build notice. |
| **Unknown** | Rejected, with a "did you mean" suggestion. |

The reserved tier lets configs from other docs platforms build using the subset
Shiso implements instead of failing on recognized features that are not
implemented yet.

Supported today: `theme`, `name`, `description`, `colors`, `logo`, `favicon`,
`navigation` and [`interaction`](/docs/navigation#collapsible-groups),
[`navbar`, `footer`, `banner`](/docs/navbar-and-footer),
[`appearance`, `fonts`, `styling`, `background`](/docs/customization),
[`redirects`, `seo`, `errors`, `metadata`](/docs/seo), and
[`search`, `contextual`](/docs/search-and-ai).

Reserved (accepted, ignored): `thumbnails`, `icons`, `api`, and `integrations`.

## Core fields

- `theme`: layout theme. Only `"shiso"` is implemented (the default)
- `name`: site title, shown in the header and page titles
- `description`: default meta description for pages without one
- `logo`: a path like `"/logo.svg"`, or per-mode paths with an optional link:

```json
{
  "logo": {
    "light": "/logo-light.svg",
    "dark": "/logo-dark.svg",
    "href": "https://example.com"
  }
}
```

- `favicon`: a path like `"/favicon.png"`
- `colors`: accent colors —

```json
{
  "colors": {
    "primary": "#16a34a",
    "light": "#4ade80",
    "dark": "#15803d"
  }
}
```

  `primary` is the semantic primary color in light mode and `light` is the
  primary color in dark mode. `dark` remains a legacy fallback when `primary`
  is omitted.

## Shiso-only options

Shiso-specific options live under the `$shiso` key, so the rest of the file
stays portable:

```json
{
  "$shiso": {
    "docsPrefix": "/docs",
    "contentDir": "content/docs",
    "siteUrl": "https://docs.example.com"
  }
}
```

- `docsPrefix`: route prefix for docs pages. Defaults to `"/docs"`; set `""`
  to serve docs at the site root.
- `contentDir`: content directory relative to the project root. Defaults to
  `"content/docs"`.
- `siteUrl`: absolute site origin. Required for canonical URLs, `og:url`,
  structured data, and `sitemap.xml` generation.

## Schema and validation

The full config format is described by `docs.schema.json` in the project root.
Point your editor at it for autocomplete and inline validation:

```json
{
  "$schema": "./docs.schema.json"
}
```

The build validates `docs.json` against the schema before anything else runs.
You can also run the check on its own:

```bash
pnpm check:config
```

## How page slugs map to files

Every value in `navigation...pages` must match a file in `content/docs`.

- `"index"` -> `content/docs/index.mdx` (or `.md`)
- `"quickstart"` -> `content/docs/quickstart.mdx` (or `.md`)
- `"components/index"` -> `content/docs/components/index.mdx` (or `.md`)

Those slugs become routes like:

- `index` -> `/docs`
- `components/index` -> `/docs/components`
- `components/callout` -> `/docs/components/callout`

## Common setup issues

- A page is listed in navigation but the file does not exist.
- A file exists but was never added to `navigation`.
- A nested slug path does not match the folder structure.

See [Troubleshooting](/docs/troubleshooting) for more.
